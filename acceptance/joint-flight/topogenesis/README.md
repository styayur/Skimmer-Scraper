# Finite flight experiment

The matrix fixes 14 development seeds, six holdout seeds, the approach, profile, number of wingmates, LB release time and expected flight behavior before tuning. Only seeds 8131 and 8132 inform revisions. The six holdouts first fly after the producer freezes its last rule. The bounded sample covers six architectural families in the stock finite GLB importer.

Every case uses a fresh browser profile, the stock world library, Keep this world, a saved-layout reopen, and the game's 120 Hz collision and flight simulation. The pilot uses a standard Gamepad mapping. The browser advances in 64 ms intervals. LB (button 4) is down for interval 4, then again for the named release interval. RT (7) is held from launch for boost. The trace includes the launch observation and 16 intervals after release. An open-air control uses a single LB pulse from a manual high-altitude launch. The yaw approach holds the yaw axis for the first four intervals. All other axes are neutral.

A mandatory case needs uninterrupted observed GLIDING through the second press, active DETACHING, a return to FLIGHT and zero impacts. A difficult case may also safely release or decline contact. An open-air control must time out without capture. A shield strike, observed hull intrusion, replay mismatch, page error or incomplete input invalidates an acceptance result. Each class has its own denominator.

The release static ZIP has SHA-256 `708ddac5ad58d51b1d7050a15f5dabf0cea36004ab2eac2dd36a8dca65a81c89`. Comparing it with the local v0.10.0 served directory matched 100 of 101 archived files byte for byte, including the HTML, both JavaScript modules and workers. The remaining file, `build-info.json`, carries the local build's toolchain and timestamp representation. Both report the same clean source commit.

## Diagnostic exchange

`flight-diagnostic-2` retains the v1 top-level SHA-256, build, browser, boost, input, fixedHz, sampleMs, releaseTick, errors, trace, imported, replayed, returnedToBuiltin and outcome. The old reader can continue consuming historical v1 reports. Each controlled report adds:

* `experiment` with numeric producer seed and ruleRevision, module, profile (`cruise` or `boost`), inputId and disposition (`must-succeed`, `may-reject`, `must-reject`).
* `world` with GLB sha256, byte length and the exact stock `glb-world:` layoutSeed. `binary` identifies the executed browser entry module by its path, byte length and SHA-256. Build.sourceCommit identifies the game source.
* `metrics` derived from the game's trace. Clearance and distance are samples, velocities are in metres per second, and acceleration is a finite difference between samples. Declared module roles and route annotations never qualify a run.

In the game, **Download player flight diagnostic** saves a local observation with `recording.kind=player`, `experiment=null` and `outcome=player-observation`. It contains the active layout, available replay identity, the actual client entry digest and a bounded trace. In a fresh browser profile, a scripted keyboard flight using the local Relay District fixture produced a [20-sample player export](catalog/player-observation.json). Producer reader `5656a74` classified it as `player-observation` with `layoutReopened=false`. Controlled replays additionally record experimental inputs, an exact saved-world replay and the return to a built-in world.

The preexisting Contact Deck and Relay District are independent controls. Both use the original V2Wpro v0.3.0 bytes. The original Lattice is regenerated by that checkout's exchange exporter. Seed 8131 identifies the design lineage for the authored controls. These controls run on the v0.10.0 binary given in the matrix. A controlled finite replay measures the recorded approach and input stream. Continuous streaming, long-flight performance and physical controller feel have separate evidence requirements.

## Reproduce

Extract the original Skimmer v0.10.0 static ZIP and serve its directory on loopback. The recorded functional flights used Python 3.14.7, Python Playwright 1.63.0, Chromium 153.0.8010.12, software WebGL and a 640 × 360 viewport. Install Playwright and its Chromium with `python -m pip install playwright==1.63.0` and `python -m playwright install chromium`. The producer runs as a separate Node process. Install its lockfile dependencies in a v0.3.0 checkout and in a second checkout at the revision-2 commit in matrix.json. The latter generator preserves all three rule revisions.

```sh
python -m http.server 4173 --bind 127.0.0.1 --directory path/to/v0.10.0-static
```

From Skimmer, in a second terminal, copy matrix.json into an empty results directory. Substitute paths to the two independent producer checkouts.

```sh
python scripts/run-topogenesis.py baseline ../V2W-v030 results/baseline
python scripts/run-topogenesis.py paired ../V2W-r2 results/aligned-r0 --revision 0
python scripts/run-topogenesis.py paired ../V2W-r2 results/aligned-r1 --revision 1
python scripts/run-topogenesis.py paired ../V2W-r2 results/aligned-r2 --revision 2
python scripts/run-topogenesis.py development ../V2W-r2 results/development --revision 2
python scripts/run-topogenesis.py holdout ../V2W-r2 results/holdout --revision 2
python -B scripts/summarize-topogenesis.py results
```

Use `--only` with a module or seed for an individual case. `--resume` reuses matching, completed controlled runs. To regenerate GLBs and independently check the archived diagnostics, pass `--verify-with ../V2W-reader/tools/read-flight-diagnostic.js` to the same batch command. The v2 reader first used here is `0ddae11cabf6c053f074b51b7e7efdd7e75da18c`. The baseline includes the historical seed-8132 cruise-designed and boost-designed decks under the same boost input.

The summary counts entries into a sampled 3.3–11 m proximity window per kilometre as a maneuver opportunity proxy. A nearby surface can still fail active capture. Solid distances are centre-to-nearest-collision distances within the game's 90 m query radius. The 3.2 m hull radius defines the sampled intrusion veto. Browser heap values, when available from Chromium's DevTools Protocol, are two point-in-time V8 samples per flight. Successful intervals in the summary refer to these finite approaches. Streaming lifetime, native performance and continuous helix traversal need separate runs.

Use `python scripts/check-partner-catalog.py http://127.0.0.1:4173 new-directory` on a build with the catalog to check actual public downloads and save its build identity and screenshot.

For the integrated v0.11.0 comparison, serve a separate static build on its own loopback port. The recorded copy of clean source `0a5272b36352a1300253080bd38cfb5d520c7e0d` contains 104 files. The [content manifest](integrated-0a5272b3/SHA256SUMS) hashes each file individually and uses LF line endings. The [runtime identity](integrated-0a5272b3/runtime.json) pins the SHA-256 and size of the JavaScript entry that the browser executed. To repeat the comparison, place runtime.json and SHA256SUMS in a new evidence directory and supply the frozen revision-2 producer checkout.

```sh
python scripts/run-topogenesis.py development ../V2W-r2 new-results/development --revision 2 --url http://127.0.0.1:43847 --controller 0a5272b36352a1300253080bd38cfb5d520c7e0d --entry-sha256 e5993c151442ba79878303908d507e016ea05a1908895891f1bab943583c15b9
python scripts/run-topogenesis.py holdout ../V2W-r2 new-results/holdout --revision 2 --url http://127.0.0.1:43847 --controller 0a5272b36352a1300253080bd38cfb5d520c7e0d --entry-sha256 e5993c151442ba79878303908d507e016ea05a1908895891f1bab943583c15b9
python -B scripts/compare-flight-controllers.py new-results --stock acceptance/joint-flight/topogenesis
```

For a new controller, `python -B scripts/freeze-flight-build.py path/to/dist new-server-directory new-results --controller <clean-SHA>` compares the source and private copy file by file and writes the runtime identity. Serve new-server-directory and use the recorded entry digest with the replay commands.

After the second holdout is revealed, pass `second-holdout`, `--sealed-cases path/to/reveal.json` and `--revision 2` to run-topogenesis.py. Save the stock runs in new-results/second-holdout-stock and the revised runs in new-results/second-holdout. Pass the same `--sealed-cases` to compare-flight-controllers.py for the independent denominator. Both commands verify the published commitment before using the inputs.

For the third panel, use the `third-holdout` batch and pass `--panel third-holdout --sealed-cases acceptance/joint-flight/topogenesis/third-holdout.json` to the comparison command. Its commitment also checks each regenerated GLB against the privately frozen size and digest.
