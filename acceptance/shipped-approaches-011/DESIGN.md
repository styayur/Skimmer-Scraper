# 三个历史导出的定向入口

本次检验 V2Wpro v0.4 的三个原始 GLB 能否从玩家可设置的入口捕获指定顶面。每个世界预选一条路线，选择依据是文件里的碰撞三角形、出生安全走廊和沿航向可用的顶面长度。探索结果只适用于实飞的入口。五条默认出生轨迹和原 34 项的计分沿用各自的永久收据。[原始五条收据](https://github.com/styayur/Skimmer-Scraper/blob/c67d8f87e5b920019a7d46a3b1b0ec9ba0608882/acceptance/final-web-011/results/main-ac943acd/shipped/readback.json)

几何清单从已封存的 GLB 读取位置和索引，检查六面的三角形，按导入器规则归一化。三个目标顶面高度依次为 9.00、19.60、1.04 米。每个起点高出目标 6.8 米。沿起飞方向每隔 2 米检查至 22 米，三条路线的最小几何间距依次为 6.800、7.354、6.942 米。Lattice 的 33 个装饰节点不参与碰撞。托管实飞前，通过正式客户端的最近实体与滑行面查询逐点核对走廊及目标前、中、后三点。各点的命中、法线、实例和三角形均留档。[几何清单](geometry.json) · [固定输入及文件指纹](plan.json)

使用 ac943acd 正式 Web 文件、普通世界库的手动位置和航向、默认缩放和姿态。保存后重载，再在独立标签页从世界库打开同一布局。标准映射手柄两次各按一整个区间的 LB（按钮 4），巡航、摇杆归零、三名僚机，释放请求后再观察 16 个区间。物理为原游戏 120 Hz。沿用原采样相位和 64 ms 诊断，每 16 ms 加读一次游戏快照和实际接触查询。记录按钮边沿前状态。读数不修改姿态、速度、物理步、网格或碰撞。

在第一次按下至第二次按下前（含第二个边沿前的状态），至少一次观测到 GLIDING 即记录捕获。归属指定顶面还要求控制器接触点落在该顶面三轴界限的 0.10 米容差内，法线 y ≥ 0.95，表面身份与碰撞查询相符，捕获时护盾未受击。连续至少三个不同时刻的目标滑行样本，且同段位置弦长之和 ≥ 5 米，才记录为持续目标滑行。主动释放要求第二个按下边沿前仍在 GLIDING，随后观测到 DETACHING 并返回 FLIGHT。另报护盾、全程最小采样距离及 3.2 米机身界线。

保存所有发起的尝试，包括导入或出生被拒、未捕获、失去接触和采集错误。只有采集基础设施出错才允许用原参数恢复，全部尝试保留。三项定向探索只回答各自路线上的问题。Contact Deck 和 Relay District 已有同一正式 Web、同一文件和同一默认输入的捕获读数，直接引用。该项使用托管 Chromium 软件渲染，测量范围为游戏行为。
